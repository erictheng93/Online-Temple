# T2 交付與驗證

2026-11-06；分支 `backend/t2`，由 T1 的 `fcba016` 建立。

## 實作

- `/ws` 嚴格比對 Origin 白名單，缺少或重複 Origin 也拒絕。
- hello 絕對期限 5 秒；非 v1 回 unsupported_version 後以 1008 關閉。
- frame 與組合訊息皆限制 16 KiB；超限 1009，binary 1003。WebSocket ping/pong 控制幀仍允許。
- 無效 JSON、錯誤欄位、握手前遊戲訊息與重複 hello 計入每連線 10 秒滑動視窗，第 21 則關閉 1008；計數佇列最多 21 筆。
- 名稱移除控制字元、trim Unicode 空白、保留最多 16 個 Unicode scalar values，空名稱為訪客。
- 五種 client、九種 server 型別；camelCase 欄位、可省略欄位、moves 的數字 0/1 tuple。ping.ts 原值回傳，serverTime 為 epoch 毫秒。
- 發送限時 1 秒；關閉幀發送後保留 50 ms 傳輸時間，再最多等待 200 ms 關閉握手，避免 Windows 超大 frame 的未讀資料造成立即 TCP reset。

T2 是協定與連線邊界：有效 hello 後可 ping/pong；move、stop、action 完成解碼但尚不執行遊戲操作。welcome、房間玩家 ID、快照與其他遊戲廣播依任務清單在 T3/T4 串接；沒有假造房間或宣稱已能多人遊玩。

## 新增測試清單

1. unicode_names：全形空白、換行、空白名稱、表情符號與 17 字元截斷。
2. invalid_window_expires：10 秒視窗與 20/21 次門檻。
3. shared_frontend_fixtures_round_trip：所有訊息型別及 optional 欄位固定資料。
4. malformed_client_fields_rejected：錯誤型別、非有限數值、未知訊息與非法 moving。
5. origin_rejected_missing_and_foreign。
6. hello_timeout：真實等待 5 秒。
7. unsupported_version_then_close：error 順序與關閉碼。
8. oversized_and_binary_close_codes：17 KiB、binary。
9. invalid_messages_ignored_until_twenty_one_and_ping_echoed。
10. fragmented_message_limit：兩段各 9,000 bytes 的總長限制。
11. exact_byte_limit_and_invalid_schema_do_not_break_session：16 KiB 邊界與 UTF-8 byte 計算。
12. 前端共用 fixture 測試：直接用現有 decode/encode 驗證同一 JSON。

固定資料沿用 net.test.ts 的 move、moves 與 welcome 範例，補齊其餘型別。CI 已加入此跨語言測試。未做弱網路延遲、慢速接收者長期負載與重連突波；後續 T5/T6/T7 仍須驗證。

## 依賴與探索

新增直接依賴 tokio-tungstenite 0.29：辨識 Axum 包裝的 Capacity 錯誤，以回傳正確 1009，並供真實 WebSocket 測試；其原已為 Axum 傳遞依賴。新增 dev-dependency futures-util（std、sink，關閉預設 feature）：測試 socket 收發，不引入執行期工作佇列。

已先使用 codebase-memory-mcp；路徑組合查詢無結果，改用 decode 符號查詢、get_code_snippet 與檔案讀取補足。API 依據：[Axum WebSocketUpgrade](https://docs.rs/axum/0.8.9/axum/extract/ws/struct.WebSocketUpgrade.html)。
