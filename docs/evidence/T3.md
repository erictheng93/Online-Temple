# T3 房間 actor 交付證據

2026-11-06，分支 `backend/t3`。以最新 main（7dbc772，含殿內場景）建立分支並合入 backend/t2，保留前端更新。

## 實作與邊界

- 每房一個 Tokio task，獨占 HashMap 玩家狀態。Lobby actor 只負責入房分配與房間登記；房間內沒有 Mutex／RwLock。
- Lobby 依建立順序詢問房間；容量由房間自己原子判斷，滿房才建立下一房。正式 main 將 Config 的 ROOM_CAPACITY 傳入，限制 1～50。
- welcome 含全房快照、伺服器產生的玩家 ID、room、epoch 毫秒與隨機 resumeToken。玩家出生 x 在 [-2,2]、z=11、heading=π、zone=courtyard。
- 同房廣播 join／leave，不跨房；離線立即移除，空房 60 秒終止 task，Lobby 每 100 ms 清除已關閉登記。突然取消連線時，房間每 100 ms 檢查已關閉接收端並清理，避免殘留名額。
- 房間與 lobby 命令佇列各 128，連線發送佇列 64。房間只用 try_send，佇列滿則移除該玩家並通知其餘人。T5 尚須補位置合併、正式慢速接收者壓測與完整背壓策略。
- rand 0.9 新列直接依賴（原為傳遞依賴），用於隨機出生點與 128-bit 玩家 ID/token。此階段尚不接受 token 恢復，T6 才實作恢復語意。
- 對齊 main 新增的 zone client/server 型別與共用 fixture，尚不執行移動、動作與 zone 切換；這些驗證和操作在 T4，批次廣播在 T5。
